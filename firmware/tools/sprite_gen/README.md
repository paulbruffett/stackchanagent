# Sprite generator

Generates Stack-chan avatar sprites via OpenRouter using Google's "nano banana"
image models. Driven by `sprites.json` — edit/add entries and re-run to produce
new assets.

## Setup

1. Provide an OpenRouter API key as `OPENROUTER_API_KEY` — either in the env or
   in a `.env` at the repo root (auto-loaded; this is where the project keeps it).
2. Drop the Rocky reference image at `reference/rocky_ref.png` (path is set by
   `reference_image` in `sprites.json`). Every body-pose sprite is generated by
   editing this reference so the character stays consistent.
3. Install deps: `pip3 install Pillow` (generator) and, for `convert.sh`,
   `pip3 install pypng lz4` (LVGLImage.py needs them).

## Transparency note

The nano-banana models emit opaque JPEG and can't produce real alpha — asking
for a "transparent background" makes them *paint a checkerboard*. So sprites are
generated on a solid flat magenta background (`key_color` in `sprites.json`,
referenced in the prompts) which the generator chroma-keys to true alpha and
saves as RGBA PNG. Keep `key_color` and the prompt's background color in sync.

## Run

```sh
python3 gen_sprites.py                 # generate every missing sprite
python3 gen_sprites.py --only rocky_busy,rocky_happy
python3 gen_sprites.py --force         # regenerate all
python3 gen_sprites.py --no-resize     # keep raw model output (don't downscale)
python3 gen_sprites.py --reference reference/rocky.jpg   # override the manifest's reference image
python3 gen_sprites.py --model google/gemini-3.1-flash-image-preview
```

PNGs land in `../../main/stackchan/avatar/skins/rocky/assets/png/`.

## Test one sprite

Generate a single sprite and pop it open in the viewer to judge it before
committing to the whole set:

```sh
python3 gen_sprites.py --only rocky_busy --force --open
```

Tweak its prompt in `sprites.json`, re-run, repeat. When happy, drop `--only`
to fill in the rest.

## Model choice

`sprites.json` defaults to `google/gemini-3-pro-image-preview` (**Nano Banana
Pro**), chosen for fidelity/reference adherence over cost. Alternatives:

- `google/gemini-3.1-flash-image-preview` — Nano Banana 2 (faster/cheaper)
- `google/gemini-2.5-flash-image` — original Nano Banana

## Sprite types

- **Body poses** (`rocky_*`): use the reference image + `global_prefix`. Emotion
  is conveyed by posture, since Rocky has no face.
- **Overlays** (`decorator_*`): `use_reference: false`, drawn from
  `overlay_prefix` only. These float over the body and are animated in code.

### Reference locks the pose — use two-pass for reorientations

With the reference image attached, the model keeps Rocky in the reference's
upright stance and refuses big reorientations (lying down, on his back, both
arms up) no matter how forcefully the prompt asks. So those poses use a
**two-pass** approach (set both fields on the sprite):

- `"use_reference": false` — **pass 1** generates the pose from the sprite's own
  text `prefix` (faceless, five legs, brown carapace + green accents). This gets
  the orientation right but the character drifts.
- `"harmonize": true` — **pass 2** feeds that posed image **+** the reference back
  to the model and asks it to repaint the creature onto the reference's exact
  design, colors, and five legs while keeping the pose. Restores fidelity.

See `rocky_dizzy`, `rocky_sad`, `rocky_sleepy`. Pass 2 doubles the cost for those
sprites; `--no-harmonize` skips it (pose-only output) for cheap iteration. The
harmonize instruction is `harmonize_prefix` in the manifest (a built-in default
is used if absent).

Tried `openai/gpt-5-image` as an alternative: it's much worse at reference
fidelity (returned a literal pile of rocks), so nano-banana + two-pass is the
way. Claude/Sonnet can't generate images at all.

## Convert PNG → firmware C arrays

`convert.sh` wraps LVGL's `LVGLImage.py` to emit LVGL v9 `RGB565A8` C arrays.
Output symbol == filename, so `rocky_busy.png` -> `rocky_busy.c` exposing
`rocky_busy`, ready for `LV_IMAGE_DECLARE(rocky_busy)` in the `RockyAvatar` skin.

```sh
pip3 install pypng        # one-time, LVGLImage.py dependency
./convert.sh              # convert every PNG in png/
./convert.sh rocky_busy   # just one
```

`.c` files land in `../../main/stackchan/avatar/skins/rocky/assets/` next to the
existing decorator assets. Override paths with `IN=`, `OUT=`, or point at a
different converter with `LVGL_IMG_CONV=`.
